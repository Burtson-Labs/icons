# Burtson design system audit and upgrade

Audit date: September 25, 2026 UTC (September 24 in America/Chicago).

## Scope and evidence

The live https://icons.burtson.ai/ catalog identified itself as 0.4.2, with 384 stroke icons and 75 brand logos. The live https://ui.burtson.ai/ site identified itself as 0.7.0, with 53 component modules. Desktop screenshots and accessible page structure were inspected for both homepages. UI Button documentation and the icon no-results flow were exercised live. The repositories linked by the sites were cloned and used as the authoritative source for this upgrade. Earlier source drops were inspected and superseded because they were materially behind the current repositories.

All 53 UI component modules, tokens, public exports, site navigation, documentation architecture, package/build configuration, and the icon gallery implementation were reviewed. Icon geometry, names, metadata, rendering, exports, and build outputs were checked by the repository validators and test suite. Every UI documentation demo mounts in the existing automated suite. This was a source and runtime audit with targeted live interaction inspection, not a claim of an exhaustive manual visit to every live page or a manual optical redraw of all 459 assets.

The source packages are full project snapshots, not just illustrative mockups. Existing package exports, licenses, brand metadata, authored icon geometry, and deployment configuration are retained. No repository was pushed, package published, or site deployed.

## Design direction

Keep the restrained Burtson identity: neutral surfaces, precise outlines, consistent spacing, restrained violet accents, readable technical type, and explicit state changes. Increase the information value of the docs and catalogs without turning enterprise screens into decoration. The same native/React icon sources continue to feed consumers. The UI components remain owned implementations with Radix behavior primitives; no new third-party UI kit or proxy was introduced.

## Validation completed

- Icons: `npm run check` passed: 384 geometries validated, build/exports/types/lint/format checks, 51 passing tests, complete CDN/site build. Existing originality heuristic emitted five review-level warnings and no failing matches. Existing brand pipeline reports nine requested logos unavailable in the pinned upstream dataset; the 75 built logos are retained.
- UI: `npm run check` passed: TypeScript, lint, formatting, 117 passing tests across six files, library build, token generation consistency, 55 registry entries (53 components plus helpers), and production docs build.
- New regression coverage: URL settings, saved icons, normalized search, keyboard controls, mobile inspector DOM behavior, clipboard failure, async submission/retry/deduplication, native refs, progress, core contrast pairs, combobox FormData, docs search, source loading, accent synchronization, tool data, approval busy state and empty pagination.
- The source icon count and geometry are unchanged. The UI keeps all existing component exports.
- Build logs are included in this project snapshot under `audit/check.log`.

## Verification limits and release checks

The browser permitted live public-site inspection but rejected opening generated local file previews. No alternative browser route was used to bypass that restriction. The rewritten layouts have therefore not received a rendered browser screenshot pass in this environment. The mobile dialog tests exercise DOM behavior with a dialog shim; they do not verify native browser focus trapping or layout. JS DOM tests cannot measure clipping, real touch interaction, layout, screen-reader announcements, or actual browser contrast.

Before merging/releasing, serve the included site and inspect at 360, 390, 768, 1024 and 1440 CSS pixels. Check light/dark and every accent, 200% zoom, keyboard-only navigation, reduced motion, forced colors, and VoiceOver or NVDA. Run axe in a real browser. Open and close the icon inspector using touch, Escape, and its Close button; test changing viewport while open. Verify copy/download from HTTPS. Check docs command search, focus return after selection, lazy-chunk failures, and long modal content. Run smoke checks in one real Burtson consuming application.

The 4.5:1 test covers selected core token pairs, not every translucent combination or state. React 18, SSR hydration, Next.js client boundaries, Safari/iOS, Android, Tauri webviews and MUI consumer integration remain explicit integration checks. Existing lightweight Markdown supports a limited safe subset; full CommonMark/GFM tables, nested lists, citations and syntax highlighting are not added here. Registry/source builds need the project's existing supported Node version; use Node 22+ with the committed lockfile.
